## Harness features the pack predates

- Agent frontmatter now supports `effort`, `memory`, `isolation: worktree`, `maxTurns`, `background`, `permissionMode`, `mcpServers`, `hooks`, `schema`.
- Skills support `context: fork` (run in a fresh subagent context), `!`-command injection at invocation, `argument-hint`, `allowed-tools`, `disable-model-invocation`.
- `EnterWorktree` / `ExitWorktree` exist; `git-worktrees` still shells `git worktree add`.
- `Monitor` covers what job-guardian builds on ScheduleWakeup by hand.
- Plugins ship hooks in `hooks/hooks.json`; cccc's SessionStart task index could move into the pack (roadmap "archive & index").
- `/skill-doctor` (v2.1.261) reports per-skill context cost and unused skills. `claude plugin validate --strict --json` exists for CI (roadmap T5). `claude plugin eval` is early access.
- `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`, `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, `subagentPromptCacheTtl` are cost levers.
- Auto permission mode is the default since 2026-08-14. `/ultraplan` removed. Workflow tool keyword is `ultracode`.
- summarizer's JSONL grep depends on a private on-disk format and mis-slugifies paths with dots or underscores.

## Model guidance since 2026-08-02

- Opus 5: expands scope unasked and delegates readily; Anthropic's countermeasure text is "stop short of actions that are clearly beyond what was asked" plus explicit delegation criteria. Self-verification prompts ("double-check") waste tokens.
- Sonnet 5: follows instructions literally; "only report high-severity" lowers recall. Recommended: find everything, filter in a second pass. Relevant to reviewer's confidence >= 80 filter.
- `effort` replaces thinking budgets; Fable 5.1 can change effort per message without a cache reset.
- Model pins in the pack (reviewer/requirements-reviewer opus, explorer haiku, researcher/summarizer sonnet, implementer inherits) match memory `user-max-5x-model-policy`. No change needed.

### B. Align with the owner's rules (same or next patch)

### C. Cut weight (data over doctrine, roadmap principle 3)

1. Move worked examples and code listings into `<skill>/examples.md`; target under 150 lines per SKILL.md.
2. Zero-use skills for two months: e, try, reflect, step-back, test-driven-development, git-worktrees, job-guardian, udocument. Options: (a) delete, (b) move to a second plugin `up-extras` in the same marketplace, (c) keep but set `disable-model-invocation: true` so they cost nothing until typed. 4. waves.md: with implementer at zero dispatches, demote to a one-paragraph pointer or delete; if parallel execution is wanted, the Workflow tool (`ultracode`) is the native path.

### D. Use the current harness

1. Agent frontmatter: `effort: high` on reviewer and requirements-reviewer, `effort: low` on explorer, `maxTurns` on explorer and researcher.
2. reviewer: two-pass review (list everything, then filter to >= 80) instead of a single threshold, per Sonnet 5 guidance.
3. `context: fork` on uverify and ureview so their transcripts stay out of the main context (memory `context-economy-subagents`).
4. git-worktrees: rebuild on `EnterWorktree` / `ExitWorktree`; implementer gets `isolation: worktree` when waves return.
5. hooks/hooks.json: SessionStart prints the task index (active tasks, archive count), replacing cccc's local hook.
6. `!` injection in make: `git branch --show-current` and the active task list at invocation instead of a manual "check the branch" step (the 2026-08-17 session's "why main" complaint).
7. CI: `claude plugin validate --strict --json` plus a dangling-reference grep and a version-bump check (roadmap T5).
8. Run `/skill-doctor` after one week of the trimmed pack to confirm the cut.
